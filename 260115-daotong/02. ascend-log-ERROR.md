从日志看，你遇到的并不是“某一个”错误，而是**三类根本性问题**同时爆发，导致 ATC（Ascend Tool Chain）在编译 SAM3 模型时直接崩溃。先把结论写在最前面：

# 根因分析
根因一句话  
**计算图里同时出现了“数据类型不一致”和“张量维度不符合算子要求”的节点**，GE/FE/TBE 在做子图融合 / 算子编译时无法自动修复，于是层层报错退出。  


下面给出逐类拆解、定位办法和修复方案，按“能立刻动手 → 需要改模型 → 需要改 ATC 参数”三级难度排序，你可以按顺序试，哪一步通过就可以停。


## 数据类型不一致（DT_INT32 vs DT_INT64）

典型日志
```shell
[OP_PROTO] The /trunk/Greater op dtype is not same, type1:DT_INT32, type2:DT_INT64  
[AICPU] The data type of input0 [DT_INT32] need be same with input1 [DT_INT64]
```

### 快速定位  
```bash
awk -F'[][]' '/dtype is not same/ {print $2}' plog-* | sort | uniq -c
```
会告诉你哪些 op 出现混用。  
Greater、Less、Equal 这类“比较”算子对输入类型要求严格一致，而 TensorFlow/PyTorch 侧常常把 const 写成 int64，把真实输入写成 int32。

### 修复办法  
a) 在模型里强制 cast  
   – TensorFlow：  
   ```python
   cast = tf.cast(tensor_int32, tf.int64)
   ```  
   – PyTorch（导出 ONNX 前）：  
   ```python
   tensor = tensor.to(torch.int64)
   ```  
b) 如果模型改不动，可以在 ATC 命令里加 **–input_dtype** 强制把整网输入抬到 int64：  
   ```bash
   atc --model=sam3.onnx \
       --framework=5 \
       --input_dtype="input0:int64,input1:int64" \
       ...
   ```  
   但这只能解决输入层，中间层仍需要模型本身保证一致，所以首选还是改模型。

## MatMulV2 编译失败（TBE 返回 exception）

典型日志
```shell
TBE(…): do single op compile failed. kernel[te_matmulv2_xxx] module[impl.dynamic.mat_mul] func[mat_mul]
```

### 根因  
TBE 动态 shape 的 MatMulV2 目前对  
- 第一维含 “-1” （batch 不确定）  
- 格式为 FRACTAL_NZ  
同时出现时，编译鲁棒性很差，直接抛异常。

### 快速验证  
把 batch 维度固定再跑一次 ATC：  
```bash
atc --model=sam3_fixed.onnx \
    --input_shape="input0:1,256,256;input1:1,256,256" \
    ...
```
如果固定形状后 MatMul 不再报错，就可以确定是动态 batch 导致。

### 生产环境解决方案  
- 首选：在业务允许范围内把 batch 设成最大上限，推理时走动态拼 batch（AscendACL 支持）。  
- 次选：把 MatMul 改成 **Conv1x1**（计算等价）或者 **GEMM**，Conv 的动态 shape 支持更成熟。  
- 末选：关融合，让 MatMul 走单算子 fallback：  
  ```bash
  export TBE_PARALLEL_COMPILE=0
  export FE_OMP_NUM_THREADS=1
  atc --op_compiler=non_parallel ...
  ```
  但性能会掉 10~30%，仅作调试。

## SwinAttentionScoreFusionPass 维度检查失败

典型日志
```shell
[OP_PROTO] The dims of bmm1_node input0 should be greater than 3.
```

### 原因  
CANN 的 SwinAttention 融合 Pass 要求输入 ≥4-D，而你的模型里传入的是 3-D 张量，直接被拒绝。

### 修复  
- 模型侧：在进 SwinAttention 之前 reshape 成 4-D  
  ```python
  # 假设原来 shape 是 [B, N, C]
  x = tf.reshape(x, [B, N, 1, C])   # 增加一个 dummy 维度
  ```  
- 或者干脆关掉该融合 Pass：  
  ```bash
  atc --model=sam3.onnx \
      --disable_fusion_passes=SwinAttentionScoreFusionPass \
      ...
  ```  
  后者最简单，但会损失 Swin 专用优化，性能可能掉 5% 左右。

# 总结 checklist

- 全局搜索 Greater/Less/Equal，保证输入 dtype 一致  ------>  **从代码分支2可以看出，dtype被强制整形为INT32，看要不要试用一下强制整形为INT64，**
- MatMulV2 输入形状含 “-1” 时，先固定 batch 跑通     ------>  **其实 atc 转换时固定了动态 batch 为 1 并做了转换，从代码分支2可以看出，规避 matmul 算子的问题，结合上面 dtype 强制整形为 INT64，看能不能做，**
- SwinAttention 输入维度 ≥4-D，否则 reshape 或关 Pass  ------>  **这个给不了什么建议，可以参考是不是通过代码将维度从 3 -> 4，然后再执行最后一个 pt、onnx、om 推理及余弦相似度比较，**
- 以上都改完后，再打开 TBE 并行编译，测性能

把这三类错误清零，SAM3 就能正常编出 .om 文件。
